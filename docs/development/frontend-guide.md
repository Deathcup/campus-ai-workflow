# 前端开发指南

## 目录与职责

```text
apps/web/src/
├── components/       # 无业务或弱业务的可复用组件
├── modules/          # 未来按 capability 拆分的模块页面
├── api.ts            # HTTP 客户端，不放页面状态
├── App.tsx           # 平台 Shell 和路由级组合
└── styles.css        # 当前设计 Token；规模增大后按模块拆分
```

新增第二个功能时，应先建立 `modules/<module-id>`，包含该模块的列表、创建页、详情页和 API hooks；不要继续把业务堆进 `App.tsx`。

## 组件规则

- 组件只做一层职责：平台 Shell、模块 Shell、业务视图或基础组件。
- 业务状态靠近模块，平台状态只保存登录用户、导航和全局配置。
- 服务端状态以 API 为真值，不在多个组件复制可变缓存。
- Props 使用明确类型；禁止 `any` 和未经校验的 `JSON.parse` 结果。
- 可复用组件不得依赖具体 module ID。

## 交互与视觉

- 全局侧栏展示能力应用；模块内部再展示会话、任务或通知。
- Agent 与模型属于应用级管理配置；普通业务页面不得要求用户选择 Runtime 或模型。
- 所有异步动作必须有 loading、disabled、success 和 error 状态。
- 当前页面的导航动作必须禁用或给出明确反馈，避免“点击无反应”。
- 危险操作二次确认；取消运行和删除配置在视觉上区分。
- 支持键盘操作、可见焦点、语义化标签和合理的对比度。
- 至少验证桌面宽屏、900px 和 680px 三个布局断点。

## API 与 SSE

- 页面只能通过 `api.ts` 或模块 API 文件访问后端。
- 请求错误统一转换为用户可读消息，原始错误写开发日志。
- SSE 断开应提示并允许重新连接；收到终态后重新拉取权威资源。
- 不把 token 放 URL；认证使用安全 Cookie 或公司网关注入的可信头。

## 测试建议

- 纯函数和状态转换：Vitest。
- 表单、禁用态和错误态：React Testing Library。
- 创建任务、SSE 终态、取消和恢复：Playwright。
- UI 变化保留关键页面截图，但截图不能包含公司数据。
