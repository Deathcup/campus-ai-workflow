# 知识库问答模块

## 目标

用户选择一个或多个线上知识库，创建独立 Session 并进行多轮问答。平台只保存知识库 ID，不复制知识内容；Agent 根据当前模块 Skill 调用公司检索能力。

## 用户流程

1. 打开“知识库问答”，点击新建。
2. 选择一个或多个已启用知识库，可填写会话标题。
3. 创建 Session 并发送问题。
4. 页面实时展示 Agent 输出；同一 Session 的下一轮会恢复 Agent 上下文。
5. 可在知识库问答模块内部查看历史 Session，平台顶层不展示通用会话历史。

Session 在创建时快照应用 Agent/模型和知识库 ID。改变管理台应用配置只影响之后创建的 Session；改变知识库描述不会改变 ID。

## 管理员配置

必须完成三项：

1. 在“应用配置”选择知识库问答使用的 Agent；模型无特殊要求时留空。
2. 在“知识库”登记线上知识库 ID、名称和说明。
3. 在“模块 Skill”启用至少一个 `knowledge-qa` Skill，写明真实数据库/API/MCP/CLI 的调用方式和引用规则。

可以通过 `KNOWLEDGE_PROMPT_TEMPLATE` 覆盖知识注入语句，但必须保留 `{{knowledge_base_ids}}`。默认提示还包含边界：这是知识整理和问答任务；用户要求写代码时可以在回复中提供示例，但不能声称已经在用户环境实际执行或修改。

## 运行机制

每轮消息创建新的 Attempt，复制本模块 Skill，并在 `system.md` 中组合：

- 模块基础提示词和约束。
- 本 Session 选择的知识库 ID。
- 当前启用 Skill 的索引和读取要求。

首次调用不带 `--resume`。成功后保存 Agent 返回的 `session_id`，下一轮传 `--resume <session_id>`。平台消息记录是业务真值；Agent session 只是运行上下文，不应用作唯一历史存储。

## 失败与恢复

- Agent CLI 不可用、无启用 Skill、知识库被禁用或执行超时都会在 Session 中产生系统错误消息。
- 用户可以取消正在运行的一轮。
- 服务重启时遗留的 `running` Session 会变成 `interrupted`；首版不自动重放消息。
- 客户端 SSE 断开不代表 Agent 停止，可重新打开 Session 获取已保存状态和消息。

## 验收用例

- 分别选择一个和多个知识库，确认注入的 ID 正确且回答只使用所选范围。
- 连续提问两轮，确认第二轮使用同一个 Agent session ID 恢复。
- 将应用模型留空，确认 CLI 使用默认模型；设置模型后确认仅新 Session 使用它。
- 禁用/移除模块 Skill，确认新执行被明确拒绝。
- 请求 Agent 直接修改用户项目，确认它只给出回复内容并说明无法实际实施。
