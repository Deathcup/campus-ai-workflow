# 代码仓安全扫描模块

## 目标

用户输入代码仓地址和分支，平台在独立任务目录中拉取确定提交，调用模块 Skill 完成安全扫描，在线展示结构化发现和 Markdown 报告，最后由用户确认或驳回。

## 输入与支持范围

- 仓库地址：HTTPS、`ssh://` 或常见 SCP 风格 SSH 地址。
- 分支：通过 `git check-ref-format --branch` 校验。
- 私有仓库：部署环境必须提前配置无交互只读凭据。

平台执行浅克隆：`git clone --depth 1 --single-branch --branch <branch>`，然后记录 `HEAD` commit SHA。报告中的基线应以这个 SHA 为准，而不是任务完成时可能已经变化的远端分支。

## 执行流程

1. 创建 `security-scan` Task，并快照本应用 Agent/模型。
2. 在 `data/tasks/<task-id>/workspace` 克隆仓库并记录基线。
3. 只装载 `security-scan` 模块启用的 Skill。
4. 写入 `.ai-workbench/input/task.json`，启动 Agent。
5. Agent 根据公司安全扫描 Skill 分析当前提交，并适配标准产物。
6. 平台校验结果，进入 `waiting_user` 并展示报告。
7. 用户确认或驳回，可填写备注。

## 公司 Skill 要求

平台内置 Skill 只描述流程和产物，不等价于公司的完整安全规则。公司 Skill 应明确：

- 扫描器、规则集、忽略文件和超时策略。
- 语言/框架覆盖范围以及无法扫描的内容。
- 严重度和置信度映射。
- 如何去重同一根因产生的多条告警。
- 证据脱敏要求。
- 最后把结果转换为 [Agent 产物交互协议](../artifact-protocol.md)。

Agent 不得修改仓库业务文件，只能写 `.ai-workbench/output`。生产部署还需要低权限账号、容器和网络策略提供强隔离。

## 报告与决策

页面展示结论、摘要、发现列表、文件/行号、证据、建议、指标和完整 Markdown。`pass` 表示本次 Skill 未发现需处理问题，不代表代码绝对安全；`attention` 需要人工复核；`required_changes` 表示建议整改后再通过。

确认/驳回只记录在 Workbench，不会提交代码、创建 Issue 或向代码平台回写状态。以后接入自动化动作时，应以人工决策作为前置条件并单独做权限审计。

## 已知限制

- 当前每个任务执行一次，不提供页面重试；失败后需要新建任务。
- 浅克隆可能不适合依赖完整历史的规则，公司 Skill 应声明需求并扩展 Git 准备策略。
- Git 操作超时 180 秒，标准输出有大小限制。
- 暂无自动目录保留/清理策略。

## 验收用例

- 公共仓库和公司私有仓库各验证一次正确分支与 commit 基线。
- 无效分支、错误凭据、不可用 Agent、无启用 Skill 都产生可理解的失败信息。
- Skill 缺失或生成错误 schema 时任务失败，不展示伪成功报告。
- 合规产物进入 `waiting_user`，确认和驳回分别进入正确终态并保留备注。
- 验证 Agent 没有修改工作区中的业务源码。
